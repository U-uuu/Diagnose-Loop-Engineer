# AutoLoop Engineer 项目整体开发阶段目标计划

项目最终目标：构建一个基于 Multi-Agent 的自主软件诊断与修复平台，实现从故障发现、根因分析、代码修改、独立审查、测试验证到人工审批的完整闭环。

按照由简单到复杂、由单机到平台的顺序，分为以下八个阶段。

## 第一阶段：CLI 工程基础建设

目标：建立规范、可扩展的 Python CLI 工程。

- 完成项目总体架构设计。
- 建立模块化目录结构。
- 配置 Python 3.12、uv 和依赖管理。
- 实现 Typer 命令行入口。
- 实现项目路径扫描。
- 建立统一配置、日志和异常处理机制。
- 建立单元测试体系。



阶段交付

&#x20;可以通过命令行启动 AutoLoop Engineer，并扫描指定项目。



## 第二阶段：故障发现与 Incident 管理

目标：让系统能够主动发现和识别软件故障。

- 实现本地日志扫描。
- 支持 JSONL 日志解析。
- 识别异常堆栈和常见错误。
- 实现故障分类与聚合。
- 建立 Incident 数据模型。
- 实现 Incident 持久化和查询。
- 支持故障去重和状态管理。



阶段交付

&#x20;可以自动扫描日志、识别故障并生成 Incident。



## 第三阶段：Agent Runtime 与智能诊断

目标：建立通用 Agent 运行能力，让系统能够理解故障。

- 统一大模型客户端。
- 建立 Agent Runtime。
- 实现统一上下文管理。
- 实现工具注册与调用机制。
- 实现 Diagnosis Agent。
- 实现 Planning Agent。
- 建立 Agent 输入输出规范。
- 接入 LangGraph 工作流。



阶段交付

&#x20;输入 Incident 后，可以自动分析根因并生成结构化修复方案。



## 第四阶段：自主代码修复与独立审查

目标：让 Agent 具备实际修改项目代码的能力。

- 实现代码文件读取和搜索工具。
- 实现代码修改工具。
- 实现 Git 分支管理。
- 实现 Git Worktree 隔离工作区。
- 实现 Coding Agent。
- 实现 Review Agent。
- 建立代码修改前后 Diff 机制。
- 实现修复失败回滚机制。



阶段交付

&#x20;Agent 可以根据修复方案修改代码，并由独立 Agent 审查修改结果。



## 第五阶段：自动测试与完整修复闭环

目标：让系统能够验证修复是否真正有效。

- 实现测试命令自动识别与执行。
- 实现构建和测试结果收集。
- 实现修复前后测试结果对比。
- 建立测试失败反馈机制。
- 实现有限次数的自动修复重试。
- 实现 Human Gate。
- 实现修复报告生成。
- 串联完整 LangGraph Workflow。



阶段交付

&#x20;实现从故障发现到代码修复、独立审查、自动测试和人工确认的完整闭环。



## 第六阶段：执行环境隔离与可靠性增强

目标：让 Agent 能够安全、可靠地执行真实项目任务。

- 引入 Docker 沙箱。
- 实现独立项目执行环境。
- 限制文件系统和命令执行范围。
- 管理任务超时和资源限制。
- 实现任务中断与恢复。
- 实现 LangGraph Checkpoint。
- 完善执行轨迹和异常恢复。
- 增强并发任务管理能力。



阶段交付

&#x20;Agent 可以在隔离环境中执行代码修改和测试，支持任务暂停、恢复与失败处理。



## 第七阶段：工程知识沉淀与自动化能力

目标：让系统能够复用历史故障经验，并支持自动触发修复。

- 建立历史 Incident 知识库。
- 实现修复经验持久化。
- 接入 Embedding。
- 接入 Milvus 向量数据库。
- 实现 Hybrid Search。
- 接入 Reranker。
- 建立 Skills 机制。
- 建立可复用 SOP。
- 支持定时扫描和事件触发。
- 支持 GitHub Actions 等 CI 事件接入。



阶段交付

&#x20;系统可以利用历史修复经验辅助新任务，并支持自动发现和触发修复。



## 第八阶段：平台化与 Java 后端集成

目标：将 CLI 核心能力升级为可供外部系统调用的 Agent 平台。

- 将 Python CLI 核心能力封装为 FastAPI 服务。
- 建立标准 HTTP API。
- 实现 Java Spring Boot 业务后端。
- 实现项目、Incident、Repair Task 管理。
- 实现任务状态持久化。
- 实现 SSE 实时执行进度推送。
- 实现人工审批管理。
- 实现 GitHub Pull Request 创建。
- 开发 Vue3 + Element Plus 管理界面。
- 实现用户、权限和操作记录管理。



阶段交付

&#x20;形成完整的自主软件诊断与修复平台。



## 整体开发路线

1. 工程基础

   第一阶段：CLI 工程
2. 故障感知

   第二阶段：Discovery + Incident
3. 智能分析

   第三阶段：Agent Runtime + Diagnosis + Planning
4. 自主执行

   第四阶段：Coding + Review
5. 闭环验证

   第五阶段：Testing + Human Gate
6. 可靠性增强

   第六阶段：Docker + Checkpoint
7. 经验与自动化

   第七阶段：RAG + Skills + SOP + 自动触发
8. 平台化

   第八阶段：FastAPI + Spring Boot + Vue3

阶段划分原则： 前五个阶段优先完成核心产品能力，第六、七阶段增强工程可靠性和自主性，第八阶段才进行平台化。

最终应当先得到一个真正能够独立运行的自主修复 Agent，再将它包装成完整平台，而不是先搭建一个功能齐全但没有核心修复能力的管理系统。
